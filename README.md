# ColorLink 雏形

Android 端最低支持 Android 14（API 34），面向自用手机，不兼容更旧系统。

在同一个局域网（或 Mac 连着手机热点）里，让 Mac 无感地连上 OPPO 手机：

- 浏览手机的照片、视频、录音；状态栏面板里有最近三张照片，点一下复制原图
- 手机截图自动进 Mac 剪贴板
- 同步通知（微信除外）；验证码短信自动识别并复制到剪贴板
- 在 Mac 上开关手机免打扰
- Mac 锁屏或睡眠时断开，解锁即重连；手机那头前台服务随之退掉
- 在 Mac 上拖动图片或文件时，状态栏面板自动弹出，拖到照片区就发到手机
- 手机平时不在通知栏常驻；连上 Mac 的那一下弹出流体云（左边彩色链环），约 6 秒后收起，之后显示「ColorLink 已连接」常驻通知

```
ColorLink/
├── PROTOCOL.md     手机 ↔ Mac 通信协议
├── design/icon/    图标设计稿（日间 / 暗色 1024）和预览
├── tools/          make-icons.swift 绘制图标，生成安卓资源和 Mac 图标的链环图层
├── android/        手机端（Kotlin，无第三方依赖）
├── mac/            Mac 状态栏 App（AppKit + SwiftUI）+ 命令行联调工具 clcheck
└── mock/           模拟手机（Python 标准库），没有手机时调试 Mac 端用
```

## 原理

```
 Mac（状态栏 App）                                   手机（连接核心，靠通知监听保活）
 ├─ 蓝牙广播固定 UUID ─────────────────────────→  系统代为扫描，扫到就唤醒 App
 ├─ Bonjour 查找 _colorlink._tcp  ←────────────  mDNS 广播自己的 IP 和端口
 ├─ 监听 UDP 8766  ←───────────────────────────  醒来 / 换网络 / 开热点时“敲门”
 ├─ HTTPS：列表 / 缩略图 / 原文件（Range） ─────→  内置 HTTPS 服务器（MediaStore）
 ├─ HTTPS POST：拖进来的文件 ──────────────────→  存进相册 / 下载目录
 └─ SSE 长连接  ←──────────────────────────────  截图、新照片、通知、分享的文字
```

- **数据全部走 Wi-Fi，全程 HTTPS**。蓝牙只用来告诉手机“Mac 在旁边”。手机的证书是自己签的（私钥在 Android 密钥库里），Mac 配对时记下证书指纹，以后只认这一张，在公共 Wi-Fi 上别人也看不到通知内容、偷不到令牌。AVPlayer 没法自定义证书校验，播放视频时由 Mac 本机 127.0.0.1 上的转发代为取数据。
- **找手机有四层兜底**：手机敲门、mDNS 发现、上次的地址、网关（Mac 连着手机热点时网关就是手机）。后两种先用不带令牌的 `/api/id` 核对设备 ID，对上了才发令牌。Mac 从睡眠中醒来、mDNS 有变化、收到敲门时会立刻重试。
- **平时不常驻通知栏**：系统绑定着通知监听服务，进程借此一直活着，HTTP 服务等都在这个进程里，空闲时不开前台服务。Mac 连上时才启动前台服务，通知做成 Android 16 实况通知（ColorOS 显示为流体云）；断开就撤掉。没开通知使用权时，退回前台服务保活（一条折叠的静默通知）。
- **手机热点**：Mac 和手机之间的流量不出手机，不耗流量。敲门会向所有局域网网卡（包括热点）广播，开关热点时也会敲门。
- **缩略图先查缓存**：手机充电时提前生成；Mac 端有内存和磁盘两级缓存，同一张图同时被请求多次也只发一次网络请求。
- **省电**：手机只在传输（列表、缩略图、原文件、收发文件）期间持有 Wi-Fi 锁和唤醒锁，传完 3 秒后释放；探活和事件流不持锁。通知、截图、充电状态都是手机有事件时推给 Mac，Mac 不定时来问，手机深睡时不会被叫醒。

## 暂停连接

手机上划进入设置，顶部「连接电脑」是总开关。旅行时关闭即可暂停网络连接、照片与通知同步、蓝牙唤醒和定时保活；配对、权限及空闲保活偏好保留。重新打开后自动恢复连接。开关关闭期间，重启手机、更新 App 或从分享菜单进入均不会自动恢复连接。

Mac 面板顶部保留原有小圆形按钮，从左到右为「免打扰」「图库」「更多」；免打扰开启时以实心月亮和强调色显示。

## ColorOS 专项优化

| ColorOS 的问题 | 对策 |
|---|---|
| 锁屏后 Wi-Fi 芯片过滤组播，Mac 的 mDNS 查询手机收不到，只能按退避间隔盲目重试 | **手机主动敲门**：醒来、换网络、蓝牙再次发现 Mac 时，发一个带 HMAC 签名的 UDP 包，Mac 收到立刻来连。模拟测试中重连从最长 15 秒降到 0.5 秒 |
| 后台设置（完全后台行为、自启动、关联启动）系统不让 App 查询，也不让直接修改 | 设置页改成**检查清单**：依次尝试打开 ColorOS 专门的设置页，打不开就退回应用详情页；每项都写明路径和不开的后果，设好后手动打勾 |
| 不知道 App 为什么被杀、还缺哪项设置 | **存活诊断**：读取系统记录的进程退出原因（Android 11+），翻译成中文并给出对应建议；设置页还显示服务已连续运行多久 |
| 通知使用权开关开着，但系统没有绑定（ColorOS 上偶尔出现） | 服务启动、换网络、敲门时检测到未绑定，就请求系统**重新绑定**；绑定断开时也立即请求重绑 |
| 没开自启动时，开机广播和蓝牙唤醒广播会被拦截 | 清单里单独列出这一项，并说明它影响蓝牙唤醒 |
| 不支持硬件过滤的机型，每收到一个蓝牙广播包都会唤醒一次 | 敲门 30 秒内最多发一轮，避免频繁唤醒耗电 |
| 手机突然断网时，Mac 收不到关闭通知，最多 90 秒后才发现 | Mac 显示“已连接”时收到敲门，判定为假连接，立即重连 |

### ColorOS 17 真机实测（PKJ110，Android 17）

| 设置项 | 实际路径 | App 能否直接打开 |
|---|---|---|
| 完全允许后台行为 | 应用详情 → 耗电管理 → 「完全允许后台行为」 | 只能打开应用详情页（耗电管理页 `exported=false`） |
| 自启动 | 设置 → 应用 → 自启动管理 → ColorLink | 不能（页面要求 signature 级权限），只能打开设置首页 |
| 关联启动 | 设置 → 应用 → 关联启动管理 → ColorLink | 同上 |

- 旧版（ColorOS 11 及更早）的候选组件在 ColorOS 17 上全都不存在，第三方 App 申请 OPPO 组件权限也拿不到（是 signature 级）。
- ColorOS 不允许 adb 直接授予运行时权限，也不允许 adb 开关 Wi‑Fi（除非在开发者选项里打开「USB 调试（安全设置）」）。
- 真机性能：12785 张照片的首页列表 221 ms；40 张缩略图 268 ms；13 MB 原图 460 ms（约 29 MB/s）。
- 覆盖安装后，进程被系统拉起并敲门，Mac 1.5 秒内重新连上。

旧版机型如果要补组件名，可以在手机上手动打开目标页面后运行下面的命令，把输出补进 [ColorOS.kt](android/app/src/main/java/com/colorlink/ColorOS.kt)：

```bash
adb shell dumpsys activity activities | grep -E "mResumedActivity|topResumedActivity"
```

```bash

```

## 装到手机上

1. 手机打开「开发者选项 → USB 调试」，用数据线连上 Mac。
2. 安装：
   ```bash
   adb install -r android/app/build/outputs/apk/debug/app-debug.apk
   ```
3. 打开 ColorLink，按设置页的检查清单逐项完成。请求照片权限时选**允许全部**，不要选“部分照片”。
4. 在 Mac 上配对，输入手机页面上显示的 6 位配对码。
   - 从旧版 PhoneLink 升级：包名改成了 `com.colorlink`，需要先卸载旧的 PhoneLink，并重新配对。
5. 用一两天后回到设置页看「存活诊断」：如果有 ★ 记录，按提示补上对应的设置。

重新编译安卓端：

```bash
cd android && ./gradlew assembleDebug
```

查看手机日志：

```bash
adb logcat -s ColorLink.Core ColorLink.Service ColorLink.Notify ColorLink.Http ColorLink.Media ColorLink.Ble ColorLink.Wake ColorLink.Knock
```

## Mac 文件保存位置

下载的照片、自动接收的截图和手机分享的文件统一直接保存到 `~/Documents/Colorlink`，不创建分类子文件夹。重名文件自动加序号。已下载的旧文件仍按原路径访问。

## 日志与反馈

- 手机：`files/logs/colorlink.log`（App 私有目录，超过 1 MB 轮换，最多 2 MB），记录启动、连接 / 断开、前台服务、敲门、配对、收文件、短信转发（不记内容）、上次被系统结束的原因。
- Mac：`~/Library/Logs/ColorLink/colorlink.log`，记录连接状态、敲门、失败原因、截图、短信（只记是否识别出验证码，不记内容）、发文件、拖拽弹出。
- **反馈时**：状态栏图标 → 右上角「⋯」→「导出诊断日志」，会直接在「文稿/Colorlink」生成带同一批次前缀的 `手机.log`、`Mac.log`、`概况.txt`。手机日志通过 `GET /api/logs`（需要令牌）取得，所以导出时手机要连着。
- 手机没连上时，也可以用数据线取：`adb shell run-as com.colorlink cat files/logs/colorlink.log`

## 已知限制 / 下一步

- **蓝牙唤醒**：用系统托管的 PendingIntent 扫描，按服务 UUID 过滤，不受 Mac 蓝牙地址轮换的影响。ColorOS 会不会限制它还要实测；不过空闲保活现在靠通知监听，蓝牙只是额外的唤醒途径。
- **流体云**：用的是 Android 16 标准的实况通知（`setRequestPromotedOngoing` + `ProgressStyle`），ColorOS 上的具体样子由系统决定，胶囊里不一定能完全做到“左 Mac 右绿灯”。这些接口在 API 36.1 才有，当前的 Gradle 插件不认 `android-37.0`，所以用反射调用；以后升级 AGP 就可以直接调用。
- **状态栏图标被刘海挡住**：状态栏图标多的时候，新图标会落在刘海左侧，被当前 App 的菜单挡住。按住 ⌘ 把 ColorLink 图标拖到右边，或者用菜单栏管理工具把它放进常显区。拖文件时面板照样会弹出来，位置在图标原本的地方附近。
- **重新生成图标**：图标（链环）由 `tools/make-icons.swift` 用代码绘制。改完造型后运行 `swift tools/make-icons.swift`。Mac 图标是 Icon Composer 格式（`mac/Resources/AppIcon.icon`，日间 / 暗色底色在 `icon.json`），`build-app.sh` 用 Xcode 的 actool 编译，所以打包需要装 Xcode；状态栏和通知栏的单色版几何分别在 `BrandIcon.swift`、`ic_link.xml`，需要同步修改。
- **令牌**存在 Mac 的 UserDefaults 里，正式版应改存钥匙串。配对那一次是「首次信任」：如果恰好有人在配对时冒充手机，Mac 会记下他的证书；之后就不会了。手机重装 ColorLink 后证书会变，Mac 会提示重新配对。
- **全盘文件浏览**（`MANAGE_EXTERNAL_STORAGE`）还没做，现在只能浏览照片、视频和录音。
- 接入 Finder 侧边栏（File Provider 扩展）、从「最近照片」直接拖出到别的 App，都还没做。
- 手机深度休眠时 CPU 暂停，20 秒一次的 ping 会延迟，Mac 可能 90 秒后才断开重连一次。这对功能没有影响，但会多一次重连，可以在实测后调整。

### 本机安装与更新

应用安装在 `/Applications/ColorLink.app`。运行原构建脚本后，若应用已安装，将自动更新该位置；首次安装可向构建脚本传入 `--install`，或在已有构建产物时执行 `./install-app.sh`。应用标识和用户设置保留；运行中的旧版本需退出并重新打开。

## Android 检查说明

- 照片与视频分别检查完整读取权限；仅授权选中媒体时保留可见范围，并在设置中提供重新选择入口。自动同步新截图需要完整照片权限。
- 部分授权的列表不复用媒体库代数缓存；读取缩略图缓存前确认当前仍有原文件访问权。
- 配对令牌、设备身份和本地数据明确排除云备份与换机迁移。
- 唯一局部 Lint 忽略是 `stopService` 的 `ImplicitSamInstance` 误报：显式 Intent 按组件匹配，不依赖对象实例身份。
- 保留 `OldTargetApi` 提示：目前 targetSdk 35。提高 targetSdk 会改变系统运行规则，需要另做真机回归；不会仅为消除提示而升级。

参考：[Android 部分照片授权](https://developer.android.com/about/versions/14/changes/partial-photo-video-access)、[备份规则](https://developer.android.com/identity/data/autobackup)、[stopService 契约](https://developer.android.com/reference/android/content/Context#stopService(android.content.Intent))。

## 相册日期

照片和视频按原始拍摄时间分组、倒序展示；缺失时依次回退到文件修改时间、导入时间。Android 从 MediaStore 的 DATE_TAKEN 读取拍摄时间并将毫秒转换为协议使用的秒；DATE_ADDED 仍只用于新增媒体检测和分页同步。新版通过 metadataVersion 触发旧列表完整刷新，不删除缩略图或修改手机原文件。参考：[Android 媒体日期字段](https://developer.android.com/reference/android/provider/MediaStore.MediaColumns#DATE_TAKEN)。

### 旧照片的日期归属

Mac 图库优先使用手机媒体索引的拍摄日期。蓝牙导入可能保留原图 EXIF，但没有填入媒体索引的 `DATE_TAKEN`；这种情况下 Mac 会读取原文件最多 256 KiB 的头部，补取 EXIF 原始拍摄时间（其次为数字化时间）。恢复的日期按设备、媒体 ID 和修改时间单独缓存，不改变原文件，也不影响按导入顺序进行的增量同步。缺少原始日期或元数据不在探测范围内时，仍回退到修改时间 / 导入时间。

### Mac 图库操作

单击切换选中项，⌘ / ⇧ 可多选，右键显示操作菜单。双击图片使用 macOS「预览」打开原图；指针悬停在图片上时按住空格使用系统 Quick Look 临时预览，松开收起（视频只显示缩略图，不为预览下载整个原视频；已下载过的照常预览），双击打开的窗口仍由「预览」管理。手机截图成功写入 Mac 剪贴板后显示「截图已复制」通知，需要在系统设置中允许 ColorLink 通知。

快速预览优先显示本机原图或缩略图，再后台补载清晰原图；展开与收回使用指针所在缩略图的屏幕位置作为 Quick Look 动画起点。

### 手机控制中心磁贴

更新 Android App 后，在控制中心的编辑界面添加「ColorLink」。磁贴使用链环 Logo，显示「已连接 / 未连接 / 已暂停 / 待配对」，总开关开启时亮起，连接状态由副标题区分。展开控制中心时读取当前状态，面板打开期间跟随连接和设置变化刷新；点击切换「连接电脑」总开关；锁屏时先解锁，关闭仍保留配对和权限。

控制中心使用单独放大 40% 的静态 Logo，不提供自定义图标动画。
